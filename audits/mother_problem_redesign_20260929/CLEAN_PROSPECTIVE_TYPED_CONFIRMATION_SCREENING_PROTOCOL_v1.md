# Clean prospective typed-confirmation screening protocol v1

Date frozen: 2026-09-30
Status: PRE-DISCOVERY / RECORD-LEVEL OUTCOME BLIND.

## 1. Purpose

Select one new scholarly ecology for a literal clean prospective confirmation of the now-closed
typed generator-relative theory:

    Sigma(g) = (Beta(g), Kappa(g))

The candidate is not selected for breadth. It is selected only if a public external researcher can
reconstruct the bindings and state/history conditions that qualify later scholarly actions.

## 2. Documentation-only discovery rule

Allowed before candidate-specific freeze:
- project documentation and policy;
- public API/schema documentation;
- repository README/tree/schema/generic workflow code;
- data dictionaries / JATS / JSON Schema / RDF ontology / DocMaps schema;
- release/distribution metadata;
- generic example structures that do not reveal candidate outcomes.

Disallowed:
- opening candidate article/review/record payloads;
- searching by article/record ID;
- querying APIs for concrete candidate episodes;
- opening provider result pages to see whether a desired sequence exists;
- selecting a time window after seeing event outcomes.

Any accidental record-level exposure is logged and removes strict freshness for that scope.

## 3. Hard gates

### G1 Independent scholarly ecology

Not Yule-Cordier, AAD, VGW, or Formalization Papers.

### G2 Stable object and exact relation target

The public model must expose stable identities for:
- the scholarly object/root;
- the later act;
- the exact prior claim/version/review/event targeted by that act.

Thread membership alone is insufficient when exact target identity is scientifically required.

### G3 Source-native relation semantics

At least two source-native scholarly action/relation families must be documented before records
are opened.

The relation semantics may not be inferred from the desired generator label.

### G4 Connected multi-step structure

Documentation must make a connected sequence of at least two scholarly acts structurally possible.

At least one later act must target or depend on a state/history structure created by an earlier
act.

### G5 Publicly auditable Beta(g)

An unauthenticated/public researcher must be able to recover the registered event/relation binding
predicates from the frozen public source.

Private platform state is not admissible evidence for Beta(g).

### G6 Publicly auditable Kappa(g)

Every state/history predicate claimed to qualify a later generator must be publicly recoverable
from the frozen source.

A platform may internally gate an action on private workflow state, but such a gate does NOT pass
this criterion.

This is a researchability requirement, not merely an execution requirement.

### G7 Signature heterogeneity

Documentation must prospectively support:
- at least one generator whose registered Kappa requires retained prior transition/history;
- at least one generator whose registered Kappa does not require that history once its live/current
  target condition is satisfied.

A candidate in which every action has the same signature is lower-value and does not pass.

### G8 Closed denominator

A complete population scope can be frozen before opening records using one of:
- immutable release/snapshot;
- versioned public index;
- repository commit;
- natural immutable time-window over a public API using immutable creation time.

No outcome-dependent subset selection.

### G9 Independent extraction/audit feasibility

Before DATA_OPEN it must be possible to specify:
- two independent extraction/qualification paths, or two independent parsers plus independent
  qualification where appropriate;
- a third documentary/raw-source audit path.

### G10 Exact-path pre-data feasibility

The candidate can implement:

    PROSPECTIVE_CONFIRMATION_MASTER_EXECUTION_PROTOCOL_v1

including:
- synthetic coverage manifest;
- exact authoritative-stack rehearsal;
- documentary audit;
- finalizer;
- artifact round-trip;
- no first-natural-case execution branch.

## 4. Special public-history rule

A workflow is SCREEN_FAIL_PUBLIC_HISTORY_UNOBSERVABLE if:

1. provider documentation states that a later action is enabled by prior events/state;
2. the decisive prior events/state are private to platform roles;
3. the public record exposes only the eventual later action or released result.

The existence of an internal causal gate does not make the history externally researchable.

Do not substitute:
- eventual decision existence;
- invitation existence;
- timestamps;
- aggregate counts

for the missing public qualifying history unless the project itself publishes those as the
registered qualification evidence.

## 5. Preferred candidate traits

Higher value:
- open peer review;
- public revision/version history;
- public author response;
- public assessment/decision;
- explicit reply/target/version links;
- public machine-readable API or immutable export;
- stable identifiers;
- source-native version/review relation semantics;
- public provenance.

## 6. Screening output

For every candidate record:
- documentation anchors;
- record content opened? yes/no;
- G1-G10 status;
- likely Beta(g);
- likely Kappa(g);
- history-required candidate action;
- history-not-required candidate action;
- public auditability assessment;
- denominator feasibility;
- freshness status;
- final screening disposition.

## 7. Stop rule

Stop broad discovery at the first candidate that passes G1-G10.

Then freeze candidate-specific:
- source scope;
- relation vocabulary;
- typed signatures;
- generator mapping;
- denominator;
- perturbations;
- coverage manifest;
- exact-path synthetic package;
- DATA_OPEN boundary.

Do not open candidate records merely to confirm positives exist.

## 8. Claim ceiling

Screening PASS establishes structural prospective feasibility only.

It does not establish:
- any positive natural sequence;
- prevalence;
- generator success;
- prospective confirmation.

Those remain unknown until the one-shot DATA_OPEN execution.
