# Manuscript strength gates v1

Date: 2026-09-26
Status: binding research-strength checklist for the current deepening branch.

The project does not stop when a predeclared check returns PASS. A result is manuscript-load-bearing only when the relevant competing explanation has also been tested.

## G1 — strong native baseline

A proposed insufficiency result is not load-bearing until the strongest lawful native/full-input method is run.

PASS requires:
- native comparator receives every input the native workflow legitimately uses;
- no deliberately weakened version is substituted;
- if native recovery is exact, that success is retained as part of the result.

## G2 — nontrivial reduced representation

A reduced representation must not be declared inadequate merely because one weak decoder fails.

PASS requires at least one of:
- a complete-input collision witness;
- a controlled same-projection/different-answer twin;
- failure of a declared decoder family after stronger lawful decoders are credited.

Prefer cases where a reduced representation sometimes succeeds and sometimes fails; universal failure can indicate an artificial task construction.

## G3 — cross-task separation

At least one representation must be evaluated on more than one scholarly task.

PASS pattern:
- the same representation is sufficient for one registered task;
- the same representation is insufficient or requires extra source-bound information for another;
- task definitions are frozen before the second result is opened.

This gate distinguishes task-relative adequacy from a generic "more metadata is better" claim.

## G4 — constructive repair

A positive repair result requires:
- correct source-side binding restores the complete registered output;
- an equally shaped wrong binding fails;
- at least one unaffected task remains invariant;
- repair information is explicitly charged rather than hidden in the decoder.

A repair that simply reopens the whole native object is an upper-bound control, not the proposed mechanism.

## G5 — transfer after freeze

Development results alone are not enough.

PASS requires:
- selector fixed without target outcomes;
- task, decoder, repair interface and metrics frozen before target inspection;
- all selected transfer units reported, including nulls and support stops.

Within-book chapters are reported as within-project transfer, not independent infrastructures.

## G6 — historical substance

The humanistic case must answer a substantive documentary question independent of the computational success pattern.

PASS requires:
- source hierarchy explicit;
- page-image verification for load-bearing historical relations;
- complete inventory denominator for any sampled revision episodes;
- unresolved/no-response/inaccessible cases retained;
- source assertion, attribution, criticism, correction and historical truth not conflated.

## G7 — measurement boundary

LLM or formal reasoning layers do not rescue a failed empirical measurement.

PASS requires:
- negative LLM result retained;
- formal consequence labelled conditional on its graph mapping and semantics;
- no model/prompt shopping after outcome;
- no human-belief claim without human evidence.

## G8 — novelty against mature neighbors

The final method must demonstrate a capability, boundary or repair result not obtained merely by renaming:
- view determinacy;
- provenance;
- native collation normalization;
- CRMinf / argumentation;
- ordinary relational joins.

If matched native/query methods recover the same result with the same lawful inputs, the contribution is empirical/methodological unless another strict capability difference is demonstrated.

## Stop rule

The paper may move to final manuscript consolidation only when G1-G8 each have either:
- PASS with an auditable result;
- or an explicit bounded limitation that does not contradict the central claim.

A green CI badge, large record count or successful preregistered gate is never sufficient by itself.
