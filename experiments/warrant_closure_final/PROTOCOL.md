# Final Paper-Money Warrant Construction Protocol v1

Date frozen: 2026-09-26
Status: PRE-FINAL-LLM; SUPERSEDES J0 PACKET DESIGN FOR CONFIRMATORY USE

## Purpose

J0 demonstrated that the computational warrant pipeline can close, but it exposed three design debts:

1. the final claim should be atomic rather than allowing an unconstrained REVISE escape;
2. overlapping 180-token retrieval windows must not count as independent evidence units;
3. a selective add-back/removal test is needed to isolate the role of PM03 rather than comparing two globally different top-k packets only.

## Atomic claim

`C_PM_ATOMIC`

> Under the supplied editorial record, Polo's specific identification of mulberry bark as material used for Yuan paper-money is admissible as evidence for the material composition of that paper-money.

This experiment does not adjudicate the broader proposition that Yuan paper-money existed.

## Admissible warrant states

- RETAIN
- DEFER
- WITHHOLD

`REVISE` is deliberately unavailable for this atomic task.

## Exact-source context

PM01 and PM02 must be supplied as exact source spans extracted from the frozen Gutenberg witnesses, not hand-compressed excerpts with ellipses.

Every evidence unit records:
- witness;
- token start/end;
- character start/end;
- SHA-256 of exact excerpt;
- source-object SHA-256.

## Unique evidence units

Retrieval still operates on the frozen 180-token / stride-90 windows.

Before adjudication, raw windows are collapsed into source-locus units.

Two windows belong to the same evidence unit when:
- they come from the same source-coordinate system; and
- their token intervals overlap by at least 50% of the shorter interval.

Connected components under this rule are merged into one evidence unit spanning the union of their source intervals.

This prevents overlapping windows from functioning as duplicated evidence.

## Equal unique-unit budget

Let U_G and U_S be the deduplicated units generated by the frozen generic and sequence-guided-domain policies respectively.

The final base budget is computed mechanically as:

`B_final = min(|U_G|, |U_S|)`

using the policy-generated candidate sets defined below.

This is a feasibility/equalization rule, not a warrant-outcome rule.

## Base candidate sets

### GENERIC_BASE

Deduplicate the generic declared-collection top-12 raw windows.

### GUIDED_BASE

Deduplicate all 12 raw windows produced by the frozen sequence-guided domain-chain policy.

Take the first B_final units in policy order for each base condition.

## Selective counterfactual controls

### GENERIC_RESCUE_PM03

Start from GENERIC_BASE.

Replace its last unit with the exact PM03 evidence unit from the guided construction.

Budget remains B_final.

### GENERIC_SHAM

Start from GENERIC_BASE.

Replace its last unit with the first eligible sequence-guided source-chain unit that:
- is not PM03;
- does not overlap PM03;
- is not already present in GENERIC_BASE.

This tests whether any later/source-chained unit is sufficient to mimic the rescue.

### GUIDED_REMOVE_PM03

Start from GUIDED_BASE.

Remove the PM03 evidence unit.

Replace it with the first eligible non-PM03 sequence-guided source-chain unit not already represented in GUIDED_BASE.

Budget remains B_final.

If no such donor exists, the removal condition is BLOCKED_CONSTRUCTION rather than silently changing the budget.

## Primary causal pattern

The strongest selective-restoration pattern is:

- GENERIC_BASE != GENERIC_RESCUE_PM03;
- GENERIC_BASE == GENERIC_SHAM;
- GUIDED_BASE != GUIDED_REMOVE_PM03;

under the same atomic claim and frozen judge contract.

A partial or null pattern is retained.
